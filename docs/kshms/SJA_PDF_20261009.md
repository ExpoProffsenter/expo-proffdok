# Egen PDF fra lagret SJA

9. oktober 2026, Europe/Oslo. Miljømål BEGGE; bare feature/Sandbox. Avgrenset neste C-punkt før HR. Ingen database-/tilgangsendring, Production, main/demo-merge eller e-postsending.

## Resultat og kontrakt

Lagret SJA får «Last ned PDF» i den eksisterende editoren, både fra sentralen og prosjektet. Ny analyse må lagres først. Ulagrede endringer, konflikt eller ubekreftet serverinnhold sperrer uttrekk. Signert/låst historikk kan leses med eksisterende lesetilgang. Nedlasting lagrer, signerer eller fullfører ingenting.

Felles innrammet oppsett viser hele analysen, arbeidstrinn, deltakere/bidrag, lagrede rutinenummer/utgaver, prosjekt, dokument-ID/revisjon og lagret prosjektleders signatur/bekreftelse/tid. Utkast merkes «UTKAST – IKKE SIGNERT». Historiske identiteter erstattes ikke med dagens profil. Bare eksplisitte dokumentfelter eksporteres.

Eksisterende `kshms_sja_detail` leses før og etter PDF-motor/logo-last. Firma, bruker, prosjekt, tilgang og hele lagrede snapshot må stemme. Nyere dokumentasjon, tilbakekalt tilgang eller sent svar etter redigering/lukking/firma-/brukerbytte stopper PDF. Firmaprofilen må tilhøre samme firma. Manglende logo gir tydelig beskjed; lagret dokumentasjon endres ikke.

## Scope

Ny `src/modules/report/kshmsSjaPdf.mjs`; avgrenset integrasjon i `KshmsSja.jsx` og eksisterende `KshmsDocumentPdfButton.jsx`. Ny permanent `critical-kshms-sja-pdf-check.mjs` importeres av eksisterende SJA-critical slik at build alltid kjører den. Ny faktisk React/jsPDF-suite. Eldre SJA-React-test tilpasses den allerede leverte sammenfoldede prosjektoversikten: tilgjengelig knappenavn og read-only antalls-RPC-er. Ingen assertion om kladd, tilgang eller signatur er fjernet/svekket. Produksjonskomponenten for prosjektoversikt er uendret.

## Utviklerbevis

- Permanent PDF-check PASS: 24 positive/negative scenarioer, eksakt revisjon/innhold/signatur, final tilgangskontroll, avbrudd, ingen mutasjons-RPC, langtekst over sider, rammer/marginer og ingen skjult JSON-lekkasje.
- Faktisk SJA-editor + knapp + ekte jsPDF PASS: signert langtekst (2 sider), utkast (1 side), signert låst prosjekt-SJA (1 side), historiske navn/rutineutgaver, utkastmerking, ulagret sperre, ny revisjon, tilgang tilbakekalt før/etter motorlast og sent svar ved lukking/inaktivitet/firma-/brukerbytte. Alle fire sider Poppler-rendret og visuelt kontrollert.
- Eksisterende SJA React og parent React PASS: lagring, nettverksfeil/retry, lokal kladd, konfliktvalg, egen signatur, tapt signeringssvar, immutable historikk, prosjekt/firma-skifte og server-first gjenåpning.
- Eksisterende dokument-PDF React PASS: fem faktiske rutine-/personal-/mal-/prosjektkontrolluttrekk med lagrede bilder, logo, langtekst, fullføring/utkast og negative vern. Ingen mutasjon.
- Full `EXPO_BACKEND_TARGET=sandbox npm run build` PASS, exit 0. React-kvalitetskontroll: eksisterende scoped avbruddsvern gjenbrukes, knapp er `type=button`, ingen nye lagrings-/signeringseffekter eller automatisk eksport.

Transport i lokale React-prøver er simulert; det er ikke innlogget Sandbox-bevis. Eksakt publiserings-/nettleserbevis føres øverst i CONTINUITY. Tidligere TEST OK beholdes. Ny avgrenset SJA-PDF-prøve står først i USER_TEST. Øvrige B/C-punkter (samlet tilsynsuttrekk, vedlegg, underskjema, påminnelser/kilder, mobil/flere brukere) består før HR.
