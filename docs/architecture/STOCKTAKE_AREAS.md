# Varetelling: områder og historikk

Miljømål BEGGE. Additiv oppdatering av eksisterende stocktake_private og RPC-kontrakter. Firmaaktivering og check_actor, katalogidentitet, kvantumsvalidering, opprinnelig line-revision og Cordel-motor beholdes.

Private RLS-tabeller areas og events har ingen direkte klient- eller service_role-grants. Offentlige SECURITY INVOKER-ruter delegerer til private, avgrensede SECURITY DEFINER-gatewayer med tom search_path og fersk aktør-/firmakontroll. De tidligere record/get-funksjonene flyttes privat som record_base/get_base med tilbakekalte klientgrants; ingen adgang til å omgå områdekontroll. Schema-USAGE alene gir ingen tabell-/basefunksjonsrettigheter.

Alle skriveruter bruker samme eksisterende sessions-radlås: opptil flere samtidige tellerforespørsler køes kort og atomisk; delantall summeres i databasen. Områdehandlinger øker både session-revisjon og område-revisjon. Vareskrivere på områder som er tatt i bruk krever korrekt eier, status counting og den eksplisitt beholdte område-revisjonen. En annen overtakelse, pause, ferdigstilling eller overtakelse tilbake sperrer tidligere utkast. Linjeretting/sletting krever i tillegg den opprinnelige line-revisjonen. Identisk kommando-ID/aktør/payload returnerer opprinnelig kvittering uten ny skriving eller historikk. Tilgang sjekkes også før replay. Forretningskonflikter bruker PT409.

Eksisterende sessions får areas_enabled=false og områder fra de registrerte plasseringene. Disse er paused, eller done hvis tellingen allerede er avsluttet. Gamle klienter kan fortsette den eksisterende kontrakten inntil en eksplisitt områdehandling aktiverer areas_enabled på den aktuelle tellingen. Deretter kreves eierskapsrevisjon også fra gamle klienter. Dette gjør innføring additiv samtidig som gammel skjerm ikke kan omgå en påbegynt overtakelse. Ingen innhold, priser, tidligere kvitteringer eller tilgangsinnstillinger nullstilles.

Events inneholder egne nye områdetransisjoner, vellykkede tellinger/rettinger/slettinger/avslutning og én baseline per gammel varelinje. Førverdier for katalogvarer avledes fra serverkatalogens identitet. Ingen klientleverte navn eller tidspunkt brukes som historisk aktør/tid. Aktøretiketten tas fra profilens e-post, med ID som reserve; tidligere detaljhistorikk rekonstrueres ikke. Avviste kommandoer lager ingen hendelse. Ingen offentlig skriverute for historikk eksisterer.

stocktake_get bevarer hele tellingen for eksport. stocktake_area_get filtrerer valgt område før 100-raders sidevisning og returnerer session_total separat. Historikk leses via stocktake_history med valgfritt område og 50-raders sider. Fersk session-share-lås holder hvert lesesvar konsistent med skrivekontrakten. allStocktakeLines beholder eksportens før/etter-revisjonskontroll.

Klienten beholder områdevalg, eierskapsrevisjon, stoppmerknader og usikker kommando i eksisterende sessionStorage per bruker/firma. Serverhenting binder ikke automatisk en gammel kladd til ny eierskapsrevisjon. Count-formen kan avbrytes etter tapt eierskap, uten å muliggjøre lagring. Historikk hentes bare når detaljen er åpen, med ferskhets-/scopekontroll. Ingen endring i innlogging, aktiv arbeidsprofil, katalog, annen modullagring, e-post eller demo-overlay.
