# Support – implementeringsscope

Miljømål: BEGGE. Baseline main 824245e8c25e3a7d83febefe1b116a1a3fd108a1,
PR #262 publisert og demo-synk verifisert i PR-ens endelige status.

## Tillatt scope

- Ny `src/modules/support/` med skjema, egne saker og Systemadmin-innboks.
- To additive integrasjoner: `src/modules/help/helpTools.js` og
  `src/modules/app/AppNewsAdmin.jsx`. Ett additivt renderpunkt i main.jsx for tilgangsstyrt supportsak fra e-postlenke. Ingen endring i bootstrap, navigasjonslogikk eller menyer.
- Eget privat `support_private`-skjema, avgrensede support-RPC-er og ny migrasjon.
- Nye Edge Functions `support-mail` og `support-inbound`, delte supporthjelpere,
  egne konfigurasjonsseksjoner. Eksisterende arbeidere/varsler endres ikke.
- Nye tester, additive CI/package-kommandoer og release-/supportdokumentasjon.

Salgsflyt, autosave, recovery, prosjekter, HR, garantier, eksisterende
tilgangsregler/RPC-er, e-postarbeidere, rutine-e-postsperre og demo-overlay er
utenfor scope. Ingen automatisk AI-besvarelse. Vedlegg er ikke med i første
leveranse; brukeren bes om å beskrive feilen. Ingen skjult vedleggslagring.

## Kontrakt

Server bestemmer avsender, firma og mottaker. Firmaadmin leser bare egne saker.
Sak og melding lagres før varsling. Intern merknad får ingen e-post og er aldri
kundesynlig. Utgående e-post får stabil idempotensnøkkel og tidsavgrenset retry.
Private mottakere, svartoken og provider-feil eksponeres aldri i klienten.
Innkommende e-post krever råkroppssignatur, kjent svaradresse med tilfeldig token,
eierens gjeldende verifiserte adresse, godkjent e-postautentisering, gjeldende
firmatilgang og unik provider-/Message-ID. Ukjent avsender får ingen responsmail.

Produksjon migreres ikke før Preview/critical QA og ny TEST OK. Sandbox-utsending
er som standard av; faktisk e-postprøve avtales eksplisitt. Produksjonsmottak og
DNS må verifiseres før direkte e-postsvar beskrives som ferdig.

## Konkret brukertest

Samme faste Preview:
https://expo-proffdok-git-fix-company-admin-scope-20261015-ringside.vercel.app/

1. Hjelp → Kontakt support → Ny henvendelse. Fyll Emne/Kategori/Beskrivelse og
   trykk Send henvendelse. Saksnummer og lagret melding skal vises. I denne
   Previewen er e-post avslått; det skal vises ærlig.
2. Systemadmin → Support · innboks og svar. Åpne saken, send et svar, legg til
   Intern merknad og sett status/ansvarlig. Bare offentlig svar vises i Hjelp.
3. Tilbake i Hjelp, åpne saken og svar. Historikken skal beholdes. Et brukersvar
   gjenåpner løst sak. Bytt app/fane mens du skriver; samme ulagrede tekst skal
   vises etter tilgangskontroll.

Faktisk innlogget Preview-prøve og faktisk e-postmottak må fortsatt dokumenteres.
Driftsaktivering, separat scheduler, hemmeligheter og mottaksdomene gjenstår;
se SUPPORT_OPERATIONS_20261016.md. Ingen merge/Production/demo-synk ennå.
